# AI Sider 知识库 PRD v2（迭代版）

> 相比 v1 的核心变化：采集路径从「确认面板制」改为「静默沉淀 + 延迟整理」；
> 补充了跨域图片、IndexedDB blob 在 MV3 下的落点、与现有 ai-bridge 桥的复用；
> 修正了优先级矛盾与几处不可行项。未做标注「v1→v2」说明的条目继承 v1。

## 0. v1 → v2 主要修订

| # | 修订 | 理由 |
|---|------|------|
| 1 | **静默快速保存从 P2 提到 P0，且成为默认路径**；确认面板改为可选的「整理」入口 | 存摘录的摩擦是这类工具的生死线；v1 把最重的路径（F8-F12 弹面板）设为必经，P0 交互反而最不顺滑 |
| 2 | 图片抓取方式明确为「content script 内 fetch → blob」；canvas 方案仅作降级 | AI 回复里的图片多为站点签名 URL / blob:，跨域 canvas 会 taint；content script 有站点 host 权限，同源 fetch 可行 |
| 3 | 采集对象从「仅选区」扩展为「整条 AI 回复的结构化 DOM」（F10 的实现基础） | 只靠 Selection 拿不到图文顺序和代码块语言；按回复容器解析 markdown 渲染结构才能生成正确的 blocks |
| 4 | 知识库入口定为侧边栏内的一种视图（顶栏溢出菜单/图标切换），不另开页面 | 复用现有 sidepanel 框架；「发送给 AI」需要和 AI 面板同处一地 |
| 5 | 搜索方案：v1 MiniSearch 保留但降为可替换项，P0 先用内存简单索引（分词 + 子串），千条级够用且零依赖 | 减少首个版本的依赖面；MiniSearch 可后续无痛换入 |
| 6 | 删除「发送时携带图片以可访问形式提供」的模糊表述 → 明确为「图片以 paste 事件注入（复用 ai-bridge 的 paste→drop 通道），注入失败则只发文字并提示」 | v1 表述无法验收；现有 ai-bridge 已有 pasteImageToInput 通道（当前随群发功能移除，需恢复为通用工具函数） |
| 7 | 新增：去重、撤销（undo）、配额水位提示的明确规则 | v1 只提「接近配额时提示」，无阈值无行为 |
| 8 | 非目标新增：不做 OCR / 图片内文字搜索；不做摘录间双向链接 | 划清边界 |

## 1. 背景与目标

继承 v1 1.1/1.2，目标压缩为一句话：**把「看到好内容」到「存下来」的成本压到一次点击，把「整理」变成可选的后置动作。**

## 2. 非目标（当前版本不做）

云端/多端同步；向量语义搜索 / embedding；富文本编辑器；音视频；协作分享；
**OCR 与图片内文字检索**；摘录间双向链接 / 图谱。

## 3. 采集交互（本次迭代的重点）

### 3.1 设计原则

1. **捕获零摩擦**：默认路径 1 次点击完成，无任何弹窗。
2. **整理延后但可达**：所有「没整理」的内容有明确的待办出口（默认项目的未整理角标）。
3. **可撤销**：任何静默写入都有同 toast 内的撤销按钮，用户敢随手存。

### 3.2 采集入口（三合一路径）

| 入口 | 触发 | 行为 |
|------|------|------|
| A. 回复级保存 | hover 任意 AI 回复气泡 → 气泡角落浮现「⚡存」按钮（与原生复制按钮同排或独立小浮层） | 解析整条回复 DOM → 静默存入默认项目 → toast「已存入知识库 ·<项目名>」附 [整理] [撤销] |
| B. 选区保存 | 选中文字 → 原生 selection 浮条（仿 macOS 查词典条）：仅 2 个按钮 [存知识库] [AI一下] | 仅保存选中文本（若选区内含 `<img>` 一并带上）→ 同上 toast |
| C. 图片保存 | 右键图片 → contextMenus「保存图片到知识库」 | 抓图 → 存入默认项目，标题自动取图片 alt/文件名 |
| D. 快捷键 | `Alt+S`（可配置） | 等价于 A（当前 hover 的回复）或 B（有选区时），给键盘党 |

- **A 是主路径**：AI 回复是结构化 markdown DOM，比选区更能保真（图文顺序、代码块语言）。
- 三个入口全部走**同一个静默保存管线**，确认面板不在管线内。

### 3.3 静默保存管线（自动元数据）

保存时自动完成，用户无感知：

1. **标题**：取回复首行非空文本，截 40 字；全图片内容取 alt。
2. **项目**：上次使用的项目（首次为「收件箱」默认项目，见 4.1）。
3. **标签**：P0 不自动打标签，仅记 `sourceModel`；避免错误标签比没有标签更糟。
4. **图片处理**：默认压缩（长边 1920 / q0.8）+ 缩略图；抓取失败的图片降级为文字占位块并在 toast 中提示「N 张图片未能保存」。
5. **去重**：同一 `sourceModel` + `plainText` 全等且时间差 < 10 分钟 → 跳过并 toast「内容未变化，已跳过」。

### 3.4 整理（原确认面板，改为后置）

两个入口：
- toast 上的 [整理]；
- 知识库列表中「收件箱 / 未整理」视图（默认项目下 `tags 为空 且 projectId 为收件箱` 的条目集中显示，带数量角标）。

整理面板 = v1 的 4.1 确认面板，交互不变（标题/项目/标签/块级编辑/图片选项），但：
- 所有字段**带合理默认值且可直接回车保存**；
- 支持在此面板把同一次会话的多条未整理摘录**合并**为一条（P1）。

## 4. 知识库管理界面

### 4.1 入口与布局

侧边栏内视图切换：顶栏溢出菜单加「知识库」，或 Ctrl 多选图标旁的固定入口。布局继承 v1 4.2（左项目 / 右卡片列表 / 顶部搜索），新增：

- **收件箱**：内置虚拟项目（不可删除），静默保存的落点；有未整理内容时图标带角标。这是「丝滑」闭环的关键——用户可以永远不整理，但想整理时一个入口全找到。
- 卡片 hover 显示快捷操作：[发送给 AI] [插入输入框] [整理] [删除]，删除同样带撤销。

### 4.2 项目

继承 v1（F15：建/改/删/置顶 + 颜色）。删除项目时二次确认，默认**把摘录移入收件箱**而非级联删除，「连摘录一起删」需勾选确认——误删图文内容的代价不可逆，默认要保守。

### 4.3 搜索与筛选

- P0：标题 + plainText + 标签 + 来源模型的内存索引搜索（简单分词 + 子串匹配，启动时按当前项目懒加载，千条 < 100ms 可达）；输入即搜（150ms debounce）。
- P1：换 MiniSearch（本地打包，无网络请求）；「含图片」「来源模型」筛选；批量删除。

### 4.4 导入导出

- 导出：JSON 完整备份（含 media 的 base64）；Markdown（图片导出为相对路径文件，打包 zip）。P0 保留 JSON + Markdown。
- 导入 JSON：P1。导入时逐条校验 schema 版本，不兼容条目跳过并汇总报告。

## 5. 与 AI 对话联动

- 知识库视图选中摘录 → [发送给当前 AI] / [插入输入框]：**复用 ai-bridge 的 fillInput 通道**（即原 aiPendingPrompt 机制），插入不自动发送。
- 多条摘录合并发送：按 `【标题】\n正文` 拼接，总长 > 20000 字符时提示用户分批发。
- 图片：P0 仅发文字并在勾选图片时提示「图片将在下一步支持」；P1 启用 paste→drop 注入（恢复 ai-bridge 中通用化的 pasteImageToInput）。

## 6. 数据模型

继承 v1 第 5 节，修订：

- `Project` 增加 `isInbox?: boolean`（收件箱）。
- `Excerpt` 增加 `sourceUrl?: string`（采集时页面 URL，便于溯源）。
- **存储落点（v1 未明确，MV3 关键约束）**：IndexedDB 必须开在 **sidepanel 扩展页面自身**（chrome-extension:// origin），而不是 AI 页面的 content script 里——content script 的 IDB 属于站点 origin，既混入站点数据又有配额与生命周期问题。采集端（content script）只做 DOM 解析与图片 fetch，把结构化结果经 `chrome.runtime.sendMessage` 交给 sidepanel 写库。这样天然绕开跨域 canvas 问题。
- 媒体 Blob 存独立 object store，摘录存 `mediaIds` 引用；写库顺序：先 media 后 excerpt，失败回滚已写 media。
- schema 版本：DB version 1 起，升级走 `onupgradeneeded` 线性迁移。

## 7. 图片处理策略

继承 v1 5.4，补充：

- 抓取优先级：content script `fetch(url)`（有 host 权限，同源/签名 URL 均可）→ 失败则 `XMLHttpRequest` → 仍失败降级为文字占位（v1 的「提示无法保存」保留，但不阻断整条摘录）。
- GIF 不压缩（压缩会丢动画），原图直存；> 10MB 仍弹确认（P1 改为 toast 内联确认，避免打断）。
- 配额水位：启动与每次写入后查 `navigator.storage.estimate()`，用量 > 80% 时在知识库页顶常驻提示条「建议导出备份」；写入本身失败（QuotaExceededError）时阻断 + 明确报错，符合 v1 第 7 节。

## 8. 非功能需求

继承 v1 第 6 节，补充两条可验收口径：

- 知识库视图首开 < 300ms：指「项目列表 + 当前项目前 50 条卡片（缩略图懒加载）」渲染完成。
- 写入可靠性：任何一步失败对用户呈现统一 toast（含原因），不允许静默丢数据；撤销栈保留最近 10 条删除/写入。

## 9. 里程碑建议（实现切分）

| 阶段 | 内容 |
|------|------|
| M1 | IDB 基建（sidepanel 侧）+ 静默保存管线（入口 A）+ 收件箱 + 卡片列表/详情/删除撤销 |
| M2 | 入口 B/C/D + 搜索 + 项目管理 + 整理面板 |
| M3 | 发送给 AI/插入输入框（文字）+ 导出 JSON/Markdown + 配额提示 |
| P1 批 | 图片注入发送、合并整理、MiniSearch、导入、批量操作 |
